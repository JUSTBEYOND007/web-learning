# 面试回答：Storybook 组件交互演示和属性说明

## 📝 标准回答模板

### 回答要点（2-3分钟）

**开场：**
> "在我们的 Aurora-UI 组件库项目中，我们采用了**自定义文档系统**的方案，同时也了解 Storybook 的实现方式。让我分别介绍一下："

**第一部分：当前项目实现（1分钟）**

> "**当前实现：自定义文档系统**
> 
> 我们创建了 `ComponentPreview` 组件作为二次封装，实现了：
> - **组件交互演示**：直接渲染组件，支持完整的用户交互
> - **源代码展示**：集成 highlight.js 实现语法高亮
> - **属性说明**：通过 title 和 description 参数提供说明
> - **统一展示**：所有组件演示保持一致的视觉风格
> 
> 优势：
> - 轻量级，无需额外依赖
> - 完全定制化，符合项目需求
> - 与现有 Vite 构建流程无缝集成"

**第二部分：Storybook 方案（1分钟）**

> "**Storybook 实现方案**（如果采用）：
> 
> 1. **交互演示**：
>    - 使用 `play` 函数配合 `@storybook/test` 实现自动化交互测试
>    - 通过 `userEvent` 模拟用户操作
>    - 使用 `expect` 验证交互结果
> 
> 2. **属性说明**：
>    - 通过 `argTypes` 配置每个属性的说明、类型、默认值
>    - 使用 JSDoc 注释自动生成 API 文档
>    - 通过 `parameters.docs.description` 添加详细描述
> 
> 3. **二次封装**：
>    - 创建 Story 模板函数，统一 Story 编写模式
>    - 封装常用场景（如变体展示、尺寸展示）
>    - 开发自定义 Addon 扩展功能（如设计 token 面板）"

**第三部分：对比和选择（30秒）**

> "**两种方案对比**：
> 
> - **自定义方案**：适合轻量级项目，需要完全控制文档站点
> - **Storybook**：适合大型项目，需要丰富的交互测试和文档生成能力
> 
> 我们选择自定义方案主要是考虑到项目的轻量级需求，但如果项目规模扩大，迁移到 Storybook 也是可行的。"

## 📋 技术细节（如果被追问）

### 自定义方案技术栈
- React + TypeScript
- highlight.js（代码高亮）
- SCSS Modules（样式隔离）
- Vite（构建工具）

### Storybook 技术栈
- `@storybook/react-vite`
- `@storybook/addon-interactions`
- `@storybook/addon-docs`
- `@storybook/test`
