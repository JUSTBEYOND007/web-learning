** 关键词  多路复用  （解决了HTTP/1.1的队头堵塞  并发传输） 二进制协议/文本协议   头部信息压缩（HPACK）大幅减少传输开销 ** 
## **1. 二进制协议 vs 文本协议**

### **HTTP/1.1**

- 基于**纯文本格式**（header + body 都是文本）
    
- 解析成本高、扩展性差
    

### **HTTP/2**

- **二进制分帧（二进制协议）**
    
- 更快、解析更高效



多路复用：HTTP/2 实现了多路复用，HTTP/2 仍然复用 TCP 连接，但是在一个连接里，客户端和服务器都可以同时发送多个请求或回应，而且不用按照顺序一一发送，这样就避免了"队头堵塞"【1】的问题。


**头部信息压缩（HPACK）大幅减少传输开销**

### **HTTP/1.1**

- Header 每次请求都要重复发送  
    （例如 Cookie、User-Agent）
    

### **HTTP/2**

- 使用 **HPACK 头部压缩算法**
    
- 公共头部只传索引
    
- 重复字段只发送差异
    

效果：减少大量冗余流量，对移动端非常友好。
