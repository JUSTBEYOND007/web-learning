# React 底层原理详解（Fiber / 可中断渲染 / diff 算法）

## 一、为什么需要 Fiber 架构？

### 1. React 16 之前的问题

在 React 16 之前，React 使用的是 **Stack Reconciler（递归协调）**：

- 渲染过程是 **同步、不可中断的**
    
- 一旦开始 diff，就必须执行完
    
- 当组件树较大时，会长时间占用 JS 主线程
    

**带来的问题：**

- 页面卡顿
    
- 滚动和输入不流畅
    
- 用户体验变差
    

---

### 2. 浏览器渲染的时间限制

- 浏览器一帧约为 **16.6ms（60fps）**
    
- 如果 JS 执行时间过长：
    
    - 浏览器无法及时响应用户操作
        
    - 导致掉帧
        

**核心矛盾：**

> React 渲染时间过长，无法给浏览器“让路”。

---

## 二、Fiber 架构是什么？

### 1. 一句话定义（面试用）

> **Fiber 是 React 的一种新的协调架构，它将组件树拆分成可被调度、可中断、可恢复的小任务单元。**

---

### 2. Fiber 的本质

- 每一个 Fiber 对应一个组件或 DOM 节点
    
- Fiber 是一个 **JS 对象**
    

```js
Fiber = {
  type,        // 组件类型
  key,
  stateNode,   // 对应的真实 DOM
  return,      // 父 Fiber
  child,       // 第一个子 Fiber
  sibling,     // 下一个兄弟 Fiber
  flags        // 副作用标记（增删改）
}
```

---

### 3. 为什么使用链表结构？

- 传统递归遍历：**不可中断**
    
- Fiber 使用 **child / sibling / return** 构成链表
    

**优势：**

- 渲染过程可以随时暂停
    
- 下次从上一次中断的位置继续执行
    

👉 这是 **可中断渲染的基础**。

---

## 三、可中断渲染是如何实现的？

### 1. React 的两个阶段（重点）

#### Render 阶段（可中断）

- 构建 Fiber 树
    
- 进行 diff 计算
    
- 标记副作用（flags）（本质是指：在 diff 过程中，把“新旧 Virtual DOM 的差异”记录下来，用来指导之后“如何修改真实 DOM”）
    
- **不会操作真实 DOM**
    

特点：

- 可以被打断
    
- 可以被优先级调度
    

---

#### Commit 阶段（不可中断）

- 根据 flags 操作真实 DOM
    
- 执行副作用（如 `useEffect`）
    
- 一次性提交更新
    

特点：

- 必须保持一致性
    
- 不能中断
    

---

### 2. Scheduler 调度机制

React 会根据以下因素决定是否继续渲染：

- 当前任务优先级
    
- 浏览器是否空闲
    
- 是否有更高优先级任务（如用户输入）
    

如果条件不满足：

- 暂停当前渲染任务
    
- 让出 JS 主线程
    
- 等待下次继续执行
    

---

### 3. 更新的优先级

- 高优先级：用户输入、点击
    
- 中优先级：网络请求响应
    
- 低优先级：动画、过渡
    

👉 Fiber 让 React 具备了 **“任务插队”** 的能力。

---

## 四、diff 算法详解

### 1. React 的 diff 假设

React 并不是完整的树 diff，而是基于以下三个假设：

1. 不同类型的节点，直接销毁重建
    
2. 同一层级的节点，按顺序比较
    
3. 使用 `key` 来提高节点复用率
    

**结果：**

- 将复杂度从 `O(n³)` 降低到 `O(n)`
    

---

### 2. diff 的核心工作

- 比较新旧 Virtual DOM
    
- 找出变化的节点：
    
    - 新增
        
    - 删除
        
    - 更新
        
- 将这些变化记录在 Fiber 的 `flags` 上
    

> diff 阶段 **不会直接操作真实 DOM**

---

### 3. key 的真正作用（高频考点）

> **key 是 Fiber 复用的依据**  key 是 React 在同一层级下，用来唯一标识 Virtual DOM 节点的标识

- key 稳定：最大程度复用 DOM
    
- key 变化：触发节点重建
    

---

## 五、三者关系总结（面试王炸）

> React 通过 Fiber 架构，将组件树拆分为可中断的小任务单元；在 render 阶段利用 Virtual DOM 和 diff 算法计算最小更新并标记副作用；在 commit 阶段再一次性更新真实 DOM。Fiber 的引入使 React 具备了调度能力和优先级控制，从而提升了复杂场景下的性能和响应性。

---

## 六、常见面试追问

### 1. 为什么 render 阶段可以中断，而 commit 不行？

> 因为 render 阶段只进行计算，不涉及真实 DOM；  
> commit 阶段涉及 DOM 操作和副作用，必须保持 UI 状态一致性。

---

### 2. useEffect 在哪个阶段执行？

- 在 commit 阶段之后
    
- 异步执行
    

---

### 3. setState 一定是异步的吗？

> 在 Fiber 架构下，大部分更新是异步可调度的，但在某些同步场景下仍可能同步执行。

---

## 七、总结一句话（背这个就够）

> Fiber 解决了 React 渲染不可中断的问题，diff 算法解决了如何高效找出变化，而 commit 阶段保证了 UI 更新的一致性。
