# JavaScript 技术笔记：解构赋值交换数组元素的“陷阱”

## 1. 问题背景
在算法题（如 LeetCode 41. 缺失的第一个正整数）中，我们经常需要使用 **原地哈希** 的思想，将数组元素交换到其“正确”的位置上。

例如：将 `nums[i]` 放到下标 `nums[i] - 1` 的位置。

### ❌ 错误写法（导致死循环/逻辑错误）
```javascript
// 意图：交换 nums[i] 和 nums[nums[i]-1]
[nums[i], nums[nums[i]-1]] = [nums[nums[i]-1], nums[i]];
```

### ✅ 正确写法
```javascript
// 写法一：调换左侧顺序（推荐）
[nums[nums[i]-1], nums[i]] = [nums[i], nums[nums[i]-1]];

// 写法二：使用临时变量（最稳妥）
let targetIndex = nums[i] - 1;
let temp = nums[i];
nums[i] = nums[targetIndex];
nums[targetIndex] = temp;
```

---

## 2. 核心原因解析

JavaScript 中的解构赋值并不是“完全同时”发生的。虽然右侧的值（RHS）会先被计算并暂存，但 **左侧（LHS）的赋值操作是从左到右依次执行的**。

### 场景模拟
假设 `nums = [2, 1, 5]`，当前 `i = 0`。
此时 `nums[i]` (即 `nums[0]`) 是 `2`。
我们的目标是：把 `2` 放到下标 `1` 的位置，把 `1` 放到下标 `0` 的位置。

#### 错误写法的执行流程：
代码：`[nums[i], nums[nums[i]-1]] = [nums[nums[i]-1], nums[i]]`

1.  **准备右侧的值（RHS）**：
    *   取出 `nums[nums[0]-1]` (即 `nums[1]`) -> 值是 `1`。
    *   取出 `nums[0]` -> 值是 `2`。
    *   暂存数组：`[1, 2]`。

2.  **开始赋值左侧第一个变量**：
    *   `nums[i]` = `1`。
    *   **关键点**：此时原数组变成了 `[1, 1, 5]`。**`nums[0]` 的值已经变了！**

3.  **开始赋值左侧第二个变量**：
    *   原本我们想赋值给下标 `2-1 = 1` 的位置。
    *   **但此时 JS 引擎重新计算索引**：`nums[i]-1`。
    *   因为第2步中 `nums[i]` 变成了 `1`，所以索引计算结果是 `1-1 = 0`。
    *   **结果**：将右侧的第二个值 `2`，赋给了 `nums[0]`。

4.  **最终结果**：
    *   `nums[0]` 先变 `1`，又变回 `2`。
    *   数组看起来没有任何变化，导致 `while` 循环条件一直满足，程序陷入**死循环 (Time Limit Exceeded)**。

---

## 3. 为什么正确写法有效？

#### 正确写法：`[nums[nums[i]-1], nums[i]] = ...`

1.  **准备右侧的值**：`[2, 1]`。
2.  **赋值左侧第一个变量** `nums[nums[i]-1]`：
    *   JS 此时读取 `nums[i]`，值是 `2`（还没被修改）。
    *   目标位置是下标 `1`。
    *   `nums[1]` 被赋值为 `2`。
3.  **赋值左侧第二个变量** `nums[i]`：
    *   `nums[0]` 被赋值为 `1`。

**交换成功！**

---

## 4. 总结与最佳实践

在 JavaScript 中使用解构赋值交换数组元素时，如果**交换的目标下标依赖于当前下标的值**（例如 `idx = arr[i]`），必须格外小心执行顺序。

### 🛡️ 避坑法则
1.  **依赖前置**：如果 `A` 的位置依赖于 `B` 的值，解构赋值时，尽量把 `A` 放在左侧的第一个位置。
    *   即：`[目标位置, 当前位置] = [当前值, 目标值]`
2.  **使用临时变量**：如果逻辑比较绕，或者不确定执行顺序，回归最传统的 `temp` 变量交换法，代码可读性更强且永不出错。

> **记忆口诀**：
> 左侧赋值有先后，索引依赖要当心。
> 若要把值换新家，先给新家赋旧值。
