### 1. 策略模式是什么（先讲概念）

**策略模式（Strategy Pattern）**的核心思想：

- 有一组“算法 / 处理逻辑”可以完成同一类事情，但具体实现不一样（比如：渲染文本 vs 渲染图片 vs 渲染文件）。
- 把这些不同实现“封装成独立策略对象（或函数）”，对外暴露统一的接口。
- 运行时根据不同的“条件 / 类型”选择对应的策略，而不是到处写 `if / switch`。

好处：
- 新增一种策略（比如新消息类型）时，只需要**新增一个实现 + 在映射表里注册**，不用改一堆 `if-else`。
- 代码职责单一、可读性好，符合“对扩展开放，对修改关闭”的思想。

### 2. 我们项目里的“策略模式”：按消息类型选择渲染策略

#### 2.1 类型定义

在 `types/chat.ts` 里，把不同消息类型统一成联合类型：

```ts
export interface ImageContent {
  type: 'image'
  content: string
}

export interface TextContent {
  type: 'text'
  content: string
}

export interface FileContent {
  type: 'file'
  content: {
    uid: string
    name: string
    size?: number
  }
}

export type MessageContent = ImageContent | TextContent | FileContent
```

> 这里 `type` 字段就是**选择策略的 key**。

#### 2.2 策略表：`allMessageContent`（真正的“策略模式”实现）

文件：`components/Bubble/content.tsx`

```ts
import type { FileContent, ImageContent, TextContent, MessageContent } from '@pc/types/chat'
import type { ReactElement } from 'react'

type ContentHandlers = {
  [K in MessageContent['type']]: (data: Extract<MessageContent, { type: K }>) => ReactElement
}

// 各种“策略”的具体实现：

const imageContent = (data: ImageContent): ReactElement => {
  const { content } = data
  return <Image src={content} />
}

const fileContent = (data: FileContent): ReactElement => {
  const { content } = data
  return <Attachments.FileCard item={content} />
}

const textContent = (data: TextContent): ReactElement => {
  const { content } = data
  // Markdown 渲染 + 高亮，省略部分细节
  const html = md.render(content)
  const processedHtml = /* ...处理代码块... */
  return <div className="markdown-content" dangerouslySetInnerHTML={{ __html: processedHtml }} />
}

// ✅ 策略映射表：不同 type → 不同渲染函数
export const allMessageContent: ContentHandlers = {
  image: imageContent,
  file: fileContent,
  text: textContent
}
```

这里的关键点：

- `imageContent / fileContent / textContent` 就是 **三个策略函数**。
- `allMessageContent` 是一个 **策略映射表**：
  - key：`'text' | 'image' | 'file'`
  - value：对应的渲染函数 `(data) => ReactElement`
- 外部只需要传入 `MessageContent`，通过 `type` 自动选择对应策略。

#### 2.3 在气泡组件中使用策略表

文件：`components/Bubble/bubble.tsx`

```ts
import { allMessageContent } from './content'
import type { MessageContent } from '@pc/types/chat'

const renderMessageContent = (content: MessageContent[]) => {
  if (!content || content.length === 0) return null

  return content.map((item, index) => (
    <div key={index}>
      {/* 关键调用：根据 item.type 选择对应策略 */}
      {allMessageContent[item.type](item as any)}
    </div>
  ))
}
```

逻辑说明：

- 每条消息的 `content` 是一个 `MessageContent[]`，内部可能是：
  - 纯文本：`[{ type: 'text', ... }]`
  - 图片：`[{ type: 'image', ... }]`
  - 文件：`[{ type: 'file', ... }]`
  - 甚至可以混合（比如文本+图片）
- 渲染时，对每个 `item`：
  - 通过 `item.type` 选择策略：`allMessageContent[item.type]`
  - 执行对应的渲染函数：`(item) => ReactElement`

### 3. 总结：如何在项目里讲“策略模式”

你可以这样对面试官描述这一块：

- 我们的聊天消息支持三种内容类型：文本、图片、文件。
- 我使用了类似“策略模式”的设计：  
  - 先定义一个 `MessageContent` 联合类型，每个内容都有一个 `type` 字段。  
  - 然后在 `content.tsx` 里写了一个 `allMessageContent` 映射表，把不同 `type` 映射到不同的渲染函数：  
    - `text` → Markdown 渲染策略  
    - `image` → 图片渲染策略  
    - `file` → 文件卡片渲染策略  
  - 在气泡组件里渲染时，不再写一大串 `if-else`，而是通过 `allMessageContent[item.type](item)` 按类型分发。
- 这样做的好处是：
  - 新增一种消息类型（比如 `video`）时，只需要：
    1. 在类型里加一个 `VideoContent`；
    2. 实现一个 `videoContent` 函数；
    3. 在 `allMessageContent` 里注册：`video: videoContent`；  
    不需要改动已有逻辑，符合“策略模式”的扩展性思想。
