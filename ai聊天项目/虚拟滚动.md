# ✅ **面试官问：不定长虚拟列表你是怎么处理消息高度的？**

你可以这样答（重点、逻辑、专业）：

---

## **① 默认高度 + 动态测量的混合方案**

由于聊天消息高度不定，我采用的是：

### **👉 先假定默认高度（例如 120px）**

还没渲染的消息，先用默认高度参与计算：

- 总高度（totalHeight）
    
- 滚动偏移量（offset）
    
- 可视区域的 startIndex / endIndex
    

这样可以保证首次渲染不计算真实高度，避免卡顿。

---

## **② 使用 ResizeObserver 动态获取真实高度（核心）**

真正的高度是在元素渲染后才能知道的，所以我给每条消息加了：

**ResizeObserver → 监听内容真实高度变化**

```ts
new ResizeObserver(([entry]) => {
  const height = entry.contentRect.height
  onHeightChange(index, height)
})
```

真实高度一旦得到，我会立即更新缓存（Map）。

---

## **③ 使用 Map 缓存所有消息的真实高度**

```ts
const sizeMap = new Map<number, number>()
```

之后再计算：

- totalHeight
    
- offsetY
    
- 索引定位
    

时会 _优先使用真实高度_，没有的才 fallback 到默认高度。

---

## **④ 通过累加高度计算偏移量**

偏移不是固定公式，而是：

```ts
let offset = 0
for (let i=0; i<index; i++) {
  offset += getItemSize(i)
}
```

这保证不管高度怎么变，都能和实际 DOM 匹配。

# ✅ **面试官问：PC端为什么会感觉“滚动条不一致”？怎么解决？**

你可以这样答：

---

## **原因是 totalHeight 在不断修正**

因为虚拟列表初期使用的是假定高度，真实高度随后才回填。

**滚动条的比例 = scrollTop / totalHeight**

当 totalHeight 动态变化时，滚动条视觉上会有轻微跳动。

这是所有不定高虚拟列表的通病（React Window 也有）。

---

## **解决和缓解手段我做了 3 个：**

### **① RAF 节流 scroll 事件**

降低 scroll 回调频率，减少跳动。

### **② 上下缓冲区（overscan）**

额外渲染上下 2~3 条消息：

- 这些内容提前拿到真实高度
    
- 可以减少滚动到时才更新的抖动
    

### **③ 高度更新即刻回写 totalHeight**

通过 useMemo + Map 缓存高度：

- 高度越早确定，滚动条越平滑
    

---
