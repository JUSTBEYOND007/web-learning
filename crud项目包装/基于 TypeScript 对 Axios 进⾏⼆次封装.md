- **TypeScript 类型扩展**：利用 TS 增强配置项，定义了 `RequestConfig` 类型，扩展了 `retry`（自定义重试次数）和 `skipErrorHandler`（特殊场景跳过全局错误处理）等字段 。
    
- **响应结构标准化**：定义了 `ResponseData<T>` 泛型接口，强制所有后端接口遵循 `code`、`message`、`data` 的标准结构，确保业务层拿到的数据具有精确的类型推导 。
    

### 2. 拦截器逻辑实现

这是封装的核心，通过请求与响应拦截器实现业务逻辑的统一处理。

- **请求拦截器**：自动从 `localStorage` 中获取 Token ，并以 `Bearer` 格式注入到请求头的 `Authorization` 字段中 。
    
- **响应拦截器（数据脱壳）**：在响应成功时，直接返回 `response.data`，让业务层代码无需关心 HTTP 协议层的包装 。同时，根据业务状态码（如 `code !== 200`）统一拦截并抛出错误 。
    

### 3. 高级功能（面试核心加分点）

文档中详细描述了两个提升系统稳健性的核心机制：

- **智能重试机制** ：
    
    - 针对网络波动导致的错误，设计了**指数退避算法**。
        
    - 重试延迟时间公式为
        
        $$1000ms \times 2^{retry}$$
        
        ，即延迟随重试次数翻倍（1s -> 2s -> 4s），平衡了请求成功率与服务器压力 。
        

4. 异常分级处理方案

将错误精细化分类，提升用户体验：

- **网络级错误**：无服务器响应时触发智能重试 。
    
- **授权错误**：401 状态码触发 Token 刷新流程 。
    
- **服务器/业务错误**：通过 `switch` 匹配状态码（如 500、403），并调用 `showError` 组件统一展示错误信息

### 2. 核心处理策略 (分三类详细展开)

你可以结合代码截图中的 `handleServerError` 逻辑，从以下三个维度深入：

- **网络级错误 (Network Level)**：
    
    - **处理逻辑**：当接口没有返回响应（如 `error.response` 不存在）时，通常是断网或 DNS 异常 。
        
    - **解决方案**：我会触发**指数退避重试机制** 。通过 `setTimeout` 配合翻倍的延迟时间（1s、2s、4s...）尝试重新请求，提高弱网环境下的成功率 。
        
- **权限级错误 (Auth Level - 401)**：
    
    - **处理逻辑**：捕获到 **401 状态码**，意味着 Access Token 已失效 。
        
    - **解决方案**：此时会进入 **Token 无感刷新流程** 。利用状态锁 `isRefreshing` 确保只发一个刷新请求，并将期间的其他并发请求存入 `retryQueue` 队列，待刷新成功后批量重发，避免用户被迫下线 。
        
- **业务/服务器错误 (Business/Server Level)**：
    
    - **处理逻辑**：针对后端返回的 HTTP 状态码（如 500、403）或自定义 code 进行映射 。
        
    - **解决方案**：通过 `switch` 语句匹配状态码。例如：500 提示“服务器错误”，403 提示“无访问权限”，并在拦截器中统一调用 `showError()` 组件展示 UI 提示（如 Toast 或 Notification） 。
